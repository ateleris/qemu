## The bug, in one paragraph

In the OLD code (`76775361`, verified by the 2026-11-13 review via
`git show`) the outer `for(;;)` file-search round loop of
`SciReport_processBox` (old SciReport.c:618) zeroes
`tm_21_6_report_L4.u16_number_of_science_data_bytes` / `.u16_number_of_spectra`
at the start of **every** round (`case 4:`, old :660-663), after the
`nFiles == 0` break (:631-632) that precedes the only reset, with the search
capacity `filenames[3]` (:616). Those two counters are the write offset into
the 4096-B L4 staging buffer `u8_BSD_L1234_dynamic_data` (old L4Report.c:260-262;
master L4Report.c:268-270) and the length/count of the TM(21,6) packet
(TM_21.c:934-935, line-identical in the old tree). A round boundary neither
materializes nor flushes, so spectrogram samples staged since the last drain
are orphaned and never sent (D1, silent loss). The fix (`706be0b5` =
master `128f30b0` here) hoists the zeroing out of the loop, once per box
(ASW SciReport.c:623-628, with the "prevent data override GH#1061" comment at
:672). The fix also kills D2, the "ghost": OLD's break at :631 precedes its
only reset, so a level-4 request that finds no files re-materializes the
previous request's staged tail via the post-box `level_4_report(..., false)`
(SciReport.c:480-491) and the final flush (:526) as a duplicate L4
structure; GREEN's per-box reset empties it → 0x543F only (:862-865).
Drains that *do* empty staging: packet-full (L4Report.c:221-263, re-appending
the triggering row), an RCR change (ASW SciReport.c:770-813), and the
box-end / request-final flush (ASW SciReport.c:857-865, :526).

## Goal

1. One collection (unpatched GREEN build, the emulator's own detector counts —
   the "C-natural" variant the AX bench could not run, TEST_PLAN §C-natural),
   a flash snapshot, then RED and GREEN each on their own copy of that
   snapshot, each sent request A (whole collection) and B (empty window after
   it), decoded with our own tooling.
2. A coded verdict (the wrapper exits non-zero unless all hold):
   - GREEN: every archived chunk appears exactly once on the relative-time
     axis; B produces **only** TM(5,2) 0x543F (no data found) and zero
     SSID-24 packets;
   - RED: only the last search round survives (3 files' chunks + the one
     carried-over time-bin sample — the bundle's "15 = 14 + 1" signature,
     TEST_PLAN §8); B produces 0x543F **plus one packet** whose L4 structure
     is byte-identical to A's last structure (D2 ghost);
   - every sample RED sends is byte-identical to GREEN's same-relative-time
     sample.
3. Reusable tooling: `l4-tc.py` (builder), `l4-decode.py` (decoder), and
   `l4-replay.sh` (the wrapper), all slot-library based, with the ELFs taken
   from the environment and nothing from the bundle committed.

## Key facts

### The TC(238,1) request and its path [C]
- Positions: TCData.h:407-420 — req u32, level u8, start s u32, subsec u16,
  detector mask u32, n boxes u8, then 10-B boxes: tmin u24, tmax u24, tunit
  u16, packed u16 `emin(5) emax(5) energy-unit-1(5)`. The extraction order
  and the box bit layout are pinned by TM_238.c:22-58 (`emin = (packed >> 10)
  & 31`, `emax = (packed >> 5) & 31`, `e_binwidth = packed & 31`, box
  validation with FID 48435 at :69-75); `REQUEST_BOX_SIZE`/`REQUEST_HEAD_SIZE`
  TM_238.h:9-14. The two energy fields are off-by-1 in the FSW (next bullet).
- IDB mapping of the bundle's requests (tcsend_238_gh1061_cnatural.txt,
  verified against the IDB v2.26.36 ZIX38001 definition,
  stix_idb_cmd_5ac.json:8617-8703): `PIX00076` req u32, `PIX00070` level u8,
  `PIX00072` start s u32, `PIX00073` subsec u16, `PIX00248` detector mask
  u32, `PIX00071` "N box structures" u8 (the repeat counter), then per box
  `PIX00077` Tmin u24, `PIX00078` Tmax u24, `PIX00079` "Tunit" u16
  (0.1-s units, used as-is), `PIX00200` Emin u5 (as-is), `PIX00201` Emax u5
  (**off-by-1**: the FSW uses `e_max++`, i.e. the wire value is the last
  *inclusive* level, SciReport.c:567-569), `PIX00202` **"Energy unit - 1"**
  u5 (**off-by-1**: the FSW uses `e_binwidth++`, so the wire value is the
  number of energy levels per bin **minus 1**, SciReport.c:571-573). The
  extraction order matches TM_238.c:22-58 field for field.
- **The energy word resolved (review MAJOR).** The bundle sends
  `PIX00200 0, PIX00201 31, PIX00202 1` → e_min 0, e_max 32 (exclusive),
  e_binwidth 2 → energyBinning = `0<<10 | 31<<5 | 1` = **0x03E1** (16 bins
  of 2), 21-B samples — exactly the capture's decoded ebin (INVESTIGATION
  §1 "ebin 0x03E1 = 16 bins of 2", 21 B) and its packet arithmetic
  (9 × 193 + 62 = 1799 samples, TEST_PLAN §8: only 21-B samples fit ~193
  into a packet; at 37 B the same budget caps near ~110). Reading PIX00202
  as a plain ediv (→ 0x3E0, 37-B samples) contradicts the capture; it is
  wrong. Note the wire box word and the TM structure's energyBinning
  coincide at 0x03E1 for this request (emax 31 = 32−1 in both encodings).
- Nothing must follow a TC(238,1): the bundle sends only `ZIX38001` pairs.
  TC(238,2) ("Report of the unprocessed data selections", no parameters)
  and TC(238,4) exist in the IDB (stix_idb_cmd_5ac.json:8705-8719) but are
  not part of the flow; TM(238,3)/(238,7) are FSW-sent reports
  (TM_238.c:81-149), not ground follow-ups.
- Acceptance → FIFO → background task: the request goes into the user
  selection list (FID 48446 when full, TMData.h:225); the background task
  services it every **30 s** (`USER_REQUEST_PROCESSING_PERIOD 300` ticks of
  the 100 ms timer, background.c:59-63, :94, :174-178) via
  `SciReport_user_selection_list_service`, which skips SAFE (SciReport.c:347-351)
  and processes exactly one request per call (peek → process all boxes →
  dequeue, :361-392). The list is (re)initialised on every CONFIGURATION
  entry from SAFE (OpModeMgmt.c:284).
- `SciReport_user_selection_process_request` inits the TM package with the
  request's start time (SciReport.c:441), walks the boxes (:446), and after
  each level-4 box calls `level_4_report(..., flush=false)` (:480-491); the
  request ends with the final flush (:526). Window arithmetic: boxes are
  24-bit 0.1-s offsets from `start_time_sec` (SciReport.c:555-556); a chunk
  beyond `u64_box_max_time` closes the box (:820-828); with `PIX00079 1`
  (bin width 0.1 s) every chunk exceeds the bin width, so **one sample per
  archived chunk** — the bundle's 1799 chunks = 1799 samples.

### The TM(21,6) SSID 24 wire format (APID 0x5BC = 1468) [C]
- Packet: CCSDS + PUS(21,6) header (16 B to the data field, TMData.h:56),
  then TM21_HEADER_SIZE 19 B of science header (TM_21.c:23): SSID u8 = 24,
  PID u16 = 91, PSC u16 = the TC's sequence control, request number u32,
  compression schema count u8, trigger u8, start time coarse u32 + fine u16,
  number of structures u16 (patched at flush, TM_21.c:145-175, :228).
  Headers: PID 91, category 12 (APID 0x5BC), TM_21.c:737-765.
- L4 structure (fill_report_L4, TM_21.c:923-939): pixelMask u16, detector
  mask u32, rcr u8, energyBinning u16, n_spectra u16, the sample bytes
  (`u16_number_of_science_data_bytes`), **closing offset u16**
  (`u16_closing_time_offset = sci_report_time_bin.duration`, L4Report.c:185).
- Sample (fill_l4_sample_buffer, L4Report.c:54-146): rel time u24 (relative
  to the packet's start time, `(delta_ms + 50) / 100` 0.1-s units, 24-bit,
  TM_21.c:37-43), compressed trigger u8, number of energies u8, one count
  byte per energy bin → for this request 16 bins of 2 levels = 16 count
  bytes = **21 B** (energyBinning = `emin<<10 | (emax_excl-1)<<5 |
  (e_binwidth-1)`, L4Report.c:187-189, with the off-by-1 fields of the box
  above). Sample max L4_SPECTROGRAMM_SIZE 37 (32 bins of 1), header
  L4_TOTAL_HEADER_SIZE 14 (L4Report.h:9-10). Space check per packet
  TM_21.c:32-35; the bundle's packets hold 9 × 193 + 62 = 1799 samples
  (TEST_PLAN §8), consistent only with 21-B samples.
- A time bin only gets data from a **non-zero count** (the count add and
  `hasData = true`, SciReport.c:196-197; zero counts are not even stored in
  the archive, RotAccuCompactor.c:290-294).
- TM(5,2) EID 0x543F (no data found): `sendNoDataFoundMessage`,
  SciReport.c:535-544, sent from the box end when `sci_report_box_had_data`
  is false (:824-826, :862-865); request errors use 0x5445/0x5440/0x5446
  (SciReport.c:377, :470).

### The archive side [C]
- Chunk layout (sci_utils.h:8-14): timestamp 6 B, duration 2 B (0.1 s),
  detector mask 4 B, RCR 2 B, 16×3-B triggers, chunk size 2 B at 62, compacted
  datums from 64. Datums (RotAccuCompactor.c:282-334): zero counts stored as
  nothing (:290-294), 2 B at count 1, 3 B below 256, 4 B above. The RCR tag
  is baked in at collection from `RateCtrl_getRCRatTime` (RotAccuCompactor.c:152-163).
- 49-block chunk per nominal integration (the model's last block number 48,
  RotAccumulator.h:42; the model appends it, stix_det.c:1716-1723); the
  accumulator task runs in NOMINAL only (RotAccumulator.c:69-72); the FSW's
  UART prints `rcr = %u` per chunk header (RotAccuCompactor.c:163, DEBUG_PRINT
  builds).
- RAW_COUNTS files: `ArchiveManager_addDetectorData` appends chunks to the
  256-KiB stream (FLASH_BLOCK_DATA_SIZE 262144, BSW FilesystemDefinition.h:19)
  and closes the file when full (ArchiveManager.c:151-152, flushDetStream
  :106-119); **mode changes** also close it (`ArchiveManager_flushFiles`, into
  SAFE OpModeMgmt.c:166, NOMINAL→CONFIGURATION OpModeMgmt.c:294). The first
  chunk after every flush/mode (re)entry is dropped
  (`detBlockSkipedFirst`, ArchiveManager.c:138-144). File names carry type,
  start SCET and duration (FilesystemDefinition.h:64-73); file search
  capacity in processBox is `filenames[FS_CONFIG_MAX_FILES * 3]` = 180
  (SciReport.c:621; FS_CONFIG_MAX_FILES 60, FilesystemDefinition.h:48) — the
  RED/GREEN builds change it to 3 [D, bundle diffs].
- RCR changes reach the request path **only via the tags baked into the
  archive**: `RateCtrl_executeRCR` runs only from the NOMINAL QL path
  (QLAccuDblBuffs.c:228-239; RateCtrl.c:443-449) and would only change
  *future* tags; the request-time drain fires on a tag change
  (SciReport.c:770-813). State rises when the QL trigger median crosses L1/L3
  (RateCtrl.c:353-407); the RCR-1 threshold is ≈17.5 k counts/s per fpga_det
  (ground-station.md "Flare recipe"), and both default knob rates (20, 2000)
  are observed with RCR bytes 0 (ground-station.md §34, detector-smoke).

### The emulator's detector scene [C][G]
- The sky draws Poisson counts per (pix, fpga_det, ebin) with pixel shares
  (8 large = 1.0, 4 small = 0.22) and ebin shares: quiet has lines at ebin
  18/19/27 and nothing in 0/31; flare is thermal 1-10 + power-law 11-25
  (stix_det.c:964-1002, :1627-1661). At 2000 cps and a 1-s integration every
  covered cell gets λ ≈ 1.6-14 → essentially all datums non-zero [I].
- Nominal integration: ends at `t ≥ IntTimeMax+1 or SUMCNT ≥ IntEventsMax`,
  and `t ≥ IntTimeMin+1` (stix_det.c:1702-1710); the FSW's defaults make it
  20 s quiet / **1 s at flare rates** — detector-smoke pins 200-tick quiet
  and 10-tick flare integrations and ≥ 40 flare integrations
  (detector-smoke.sh:82-93). One 49-block chunk per swap; the truth traces
  are `stixdet_chunk`, `stixdet_chunk_drop`, `stixdet_nominal_swap`
  (detector-smoke.sh:82-84).
- Knobs on `/machine/stixctrl`: `det-source` (zero/synthetic/replay-dss),
  `det-flare`, `det-quiet-cps` (0..1e6, default 20), `det-flare-cps`
  (default 2000) (ground-station.md "The knobs"); the scene survives a
  device reset.
- Observed cost at flare: the flash grows by a 256-KiB NAND block about
  every 7 s (ground-station.md §34) ≈ one ~36 KB chunk/s [G] — consistent
  with the full-cell estimate 64 + 12288×3 ≈ 36.9 KB [I]. → ~7 chunks per
  file, a file every ~7 s, 12 files in ≈ 90 s of collection. Exact size [L].

## Decisions (D-L4)

- **D-L4a: the builder is `scripts/stix/l4-tc.py`, stdlib-only, CRC via
  `tcbuild.py`'s algorithm.** It builds TC(238,1) from named fields in
  TM_238.c:22-58 order (u32/u8/u32/u16/u32/u8 + 10-B boxes with the packed
  energy word) and TC(237,13) (the ZIX37013 line with `PIX00462 0xFFF`, so
  the L4 pixel mask is populated — positions TCData.h:369-387, the value set
  from the bundle's collect tcl; TEST_PLAN §8 caveat). The unit test pins
  the byte layout with the **capture-derived** 611/711 vectors: emin 0,
  emax 31, energy-unit-1 1 → box energy word bytes `03 E1` (=
  energyBinning 0x03E1 of the bundle's captures), full application data
  asserted byte for byte as derived from TM_238.c:22-58 plus the IDB
  ZIX38001 field list (stix_idb_cmd_5ac.json:8617-8703), CRC trailer
  included. A wrong energy-word interpretation (e.g. plain ediv) breaks the
  0x03E1 assertion.
- **D-L4b: our own decoder `scripts/stix/l4-decode.py`.** Parses the probe's
  0x5BC dumps (and the bundle's `.asc` captures — the same whole-CCSDS-hex
  framing) at SSID-24
  structure level per the wire format above; computes per-request sample
  totals, the relative-time series vs the expected set derived from the
  truth file, per-structure RCR, the 0x543F count, and the ghost check —
  **primary: B's single L4 structure byte-identical to A's last structure
  including the relative-time bytes and the closing offset** (the bundle's
  §8 "exact copy of 711's structure"; only the packet header's start-time
  label carries B's start time, and that is outside the structure);
  **fallback leniency: if the primary fails only in the rel-time bytes**,
  the wrapper reports the byte-identical-minus-rel-times result as a
  probable ghost and names the difference, but the PASS verdict still
  requires the primary. Its self-test uses tiny synthetic packets
  built in the test plus the bundle README's expected-output numbers
  (1799/15/ghost) as documented vectors. Cross-check (reviewer, not a gate):
  `python3 -I <bundle>/analysis/verify_l4_20261110.py` and our decoder on the
  bundle's `results/*.asc` must agree on packet/sample counts; the bundle's
  code is run **isolated (`python3 -I`), from its own directory, never
  imported by repo code, never committed**.
- **D-L4c: the wrapper `scripts/stix/l4-replay.sh`** (slot library,
  `--dry-run`/`--check-guard`, exit 77 SKIP when the ELFs are absent), four
  phases:
  1. **collect** — fresh flash in the collect run dir; boot GREEN (env
     `STIX_L4_COLLECT_ELF`, default the GREEN ELF; collection behaviour is
     identical in RED and GREEN, bundle builds table); nominal-smoke's
     connect group and mode TCs; NOMINAL at +70 s; `det-flare true` over QMP
     at +75 s (detector-smoke's QMP group pattern); hold
     `STIX_L4_COLLECT_SECONDS` (default 600); CONF at the end to flush.
     QEMU traces `stixdet_chunk`, `stixdet_chunk_drop`, `stixdet_nominal_swap`.
  2. **truth + snapshot** — from the collect UART/trace build the truth
     file: per-chunk start SCETs (the `rcr =` lines, the `File timestamp in
     archive buffer` / `Flush DET stream` lines) and the per-file boundaries;
     never from TM. **The truth counts archived chunks only, which excludes
     the chunk the FSW drops at NOMINAL entry** ("Skipped first Det data
     chunk", ArchiveManager.c:138-144 — expected exactly once per
     collection, and one less than the model-side `stixdet_chunk` count;
     the wrapper asserts that −1 reconciliation). Gate before any request
     run (the bundle's "count the files" discipline, TEST_PLAN §C-natural
     step 3): ≥ 12 RAW_COUNTS files, all chunk tags RCR 0, no RCR-change
     lines, no `*E` from the chunk path. Then `cp --sparse=always flash.bin
     flash-collect.bin` (slot.sh's sparse rules).
  3. **requests** — for BUILD ∈ {RED (`STIX_L4_RED_ELF`), GREEN
     (`STIX_L4_GREEN_ELF`)}: fresh run dir, flash.bin = a sparse copy of the
     snapshot; boot to **CONFIGURATION only** (no NOMINAL entry: no context
     write, no detector, the archive frozen). **No hard boot-event
     expects** (the probe-connect race): the connect group carries no
     expectations; after the run the probe log is grep-checked
     **advisory-only** for 0x0022 and 0x14A3 (recorded in the run record,
     never gating — review MINOR). The hard expects attach to the sends
     only: CONF at +50 (TM(1,1)/0021 02 04/TM(1,7), forbid 0021 04 02),
     S20=0 (parity) at +60, ZIX37013 PIX00462 0xFFF at +65, request A
     (start = the truth's first archived chunk SCET, tmin 0, tmax 90000,
     tunit 1, det mask 0xFFFFFFFF, 1 box) at +70, request B (start = data
     end + 600 s, tmax 600) at `STIX_L4_REQ_B_AT` (default +600 — well
     after A's 30-s service slot); probe dumps 0x5BC (L4) and 0x5A7
     (events) and expects the TM(1,1)/TM(1,7) acks; forbids 0x142E and
     0021 05 02 from CONF on (the snapshot context's stored S20=0 keeps
     the TC20 shutdown away [L]); **no other DPL=4 request between A and
     B** (the bundle's ghost precondition). Verdicts never depend on
     boot-time TM: only packets after the sends matter.
  4. **verdict** — run `l4-decode.py` per build against the truth file and
     apply the Goal-2 rules; print `L4-REPLAY: PASS/FAIL (...)` with the
     per-build numbers; keep every artefact in the run dir.
- **D-L4d: no CONF↔NOMINAL toggling for file cuts.** At the flare rate the
  dense chunks close a file at block-full every ~7 chunks (~7 s), so toggling
  buys nothing and costs a dropped first chunk per re-entry
  (ArchiveManager.c:138-144) plus mode overhead. Toggling stays a documented
  fallback if the live chunk size comes out far below the estimate [L].
- **D-L4e: RCR stillness by rate, not by patch.** The knobs keep every chunk
  tag at RCR 0 (2000 cps ≪ 17.5 k; both defaults observed RCR 0), the
  collection is continuous NOMINAL, and the post-hoc check re-verifies from
  the decoded rcr bytes and the UART (TEST_PLAN §C-natural step 5).
- **D-L4f: the long leg (optional, L4-4) uses the stock gate ELF**
  (`STIX_DEFAULT_ELF`, the v186-based build, 180-file rounds): it needs
  > 180 files ≈ 1260 chunks ≈ 21 min of collection at the flare rate [I] to
  show the original flight-size loss — at this track's 1 chunk/s the ~191
  samples ≈ packet-full are ≈ **3.2 min of spectrogram per boundary** (the
  bundle's "≈ 16 min" figure is its 5-s chunk cadence, TEST_PLAN §B). No

## Amendment A (2026-11-13, first live collect): the truth comes from the flash

**Finding.** The first live `--collect-only` (GREEN, 600 s flare) produced
605 `stixdet_chunk` trace lines but **no** `rcr =` and no `Flush DET stream`
UART line: those are plain `TRACE` calls (RotAccuCompactor.c:163,
ArchiveManager.c:113), compiled out in these builds (`TRACE` is defined
empty per file, e.g. commonCallbacks.c:18; only `TRACE_ERROR` such as
"Skipped first Det data chunk" reaches the UART). None of the three bundle
ELFs contains either format string (checked with `strings`). The L4-3
truth builder therefore cannot work; the probe and UART checks of the run
passed.

**Second finding (L4-3 review, verified in the old tree).** The wrapped
builds search the files in rounds of at most 3 (`filenames[3]`) and zero
the L4 counters at every round start (SciReport.c, 76775361, the
`case 4:` inside the search loop), so RED keeps the **last round**:
the last `nfiles % 3` files (3 when 0) + 1 carried sample. The bundle's
"15 = 14 + 1" is the `360 % 3 = 0` case. L4-3 now computes `lastround`.

**Decision D-L4-A.** The truth is read from the **collect flash snapshot**
(`flash-collect.bin`), the archive the requests themselves will read, never
from TM:
- enumerate the RAW_COUNTS files the FSW stored (type, name = start SCET +
  duration, FilesystemDefinition.h:64-73) with the FSW's own on-flash
  layout, reusing the layout code of `scripts/stix/flash-damage.py`
  (a read-only `list` subcommand, or a shared module);
- walk each file's chunks by the chunk header (sci_utils.h:8-14: timestamp
  6 B, duration 2 B, mask 4 B, RCR 2 B, triggers, chunk size 2 B at 62)
  → per chunk: SCET, RCR; per file: name, start, chunk count;
- cross-check against the `stixdet_chunk` trace: every archived chunk's
  SCET must be a model chunk's SCET, the missing ones exactly the dropped
  first chunk of each flush epoch (count asserted against the UART's
  "Skipped first Det data chunk" lines, which do print);
- the truth file format for l4-decode.py stays as it is.
Open questions for the review: (Q-A1) how the FSW locates a file's pages
(block header vs spare `pageAddress`, File.c/MemFilesystem.c — cite);
(Q-A2) whether a file's data is contiguous in the 256-KiB block and where
its valid length is recorded (the last chunk may be partial or padded);
(Q-A3) the chunk timestamp encoding (coarse/fine vs 0.1 s) relative to
the trace's `scet 0xC:0xF`; (Q-A4) the BCH/ECC layer: read data as the FSW
sees it (flash-damage.py already models the word-swapped BCH), but a
truth reader needs no correction on an undamaged image — confirm.
