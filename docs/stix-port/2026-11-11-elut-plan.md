## Goal

1. A host tool turns the flight ELUT CSV into the TC(237,7) × 96 +
   TC(237,8) sequence. It checks an SRAM dump of the FPGA ELUT against the
   CSV, through the FSW's `fpga_det` → `subcol` mapping.
2. An optional gate proves the whole chain on a fresh flash: upload,
   apply, NOMINAL entry, reboot on the same flash, and the ELUT back in
   the FPGA from flash with no upload.
3. A documented recipe that leaves a seeded flash. A sparse copy of it is
   a reusable "template flash" (`--save-template`).

## Index spaces

Des §1 and DP "Index spaces". The Caliste → indices → science channel
chain is **not 1:1**, and detector/pixel numbering has caused confusion
before. **Every variable, CLI option, log column and doc table in this
track names its index space.** A bare "det", "detector", "pixel" or
"channel" is not allowed, except when quoting a CSV header.

| Name | Space | Range | Where it appears here |
|---|---|---|---|
| `subcol` | ASW sub-collimator = ICD detector index (number − 1) | 0-31 | CSV column `Detector` [G/D, Des §1.1]; first index of the FSW RAM table `ELUT[subcol][pix][33]` (LUTMgmt.c:51) [C] |
| `det_id_1based` | ICD detector number = `subcol` + 1 | 1-32 | TC(237,7) byte "Detector ID"; the FSW does `− 1` with a uint32 wrap (LUTMgmt.c:1032) [C] |
| `fpga_det` | FPGA detector | 0-31 | dimension 1 of the FPGA ELUT `val[pix][fpga_det][adc]` at 0xE0000000 (BSW Detectors.c:386-394, Detectors.h:49-52, :109) [C] |
| `pix` | Caliste pixel | 0-11 (12 = guard ring, not in the ELUT) | CSV column `Pixel`; TC "Pixel ID"; dimension 0 of both tables (LUTMgmt.c:1033, :922-925) [C] |
| `ebin` | science energy bin | 0-31, 32 = unassigned | the FPGA ELUT value (LUTMgmt.c:883-925) [C] |
| `adc` | raw 12-bit ADC | 0-4095 | dimension 2 of the FPGA ELUT; CSV edges are `adc` values [V] |

**The non-1:1 step.** `applyELUT` loops `fpga_det` and reads row
`subcol = utils_subcolIdFromFpgaId[fpga_det]` (LUTMgmt.c:870; table
utils.c:113-119, inverse `utils_fpgaIdFromSubcolId` utils.c:121-127) [C].
- The fixed points are only `fpga_det` = `subcol` ∈ {0, 1, 4} [C]. **An
  identity mapping anywhere would silently mis-bin 29 of 32 detectors.**
  Examples: `fpga_det` 2 ← `subcol` 5, `fpga_det` 14 ← `subcol` 2.
- **The wrong-direction mistake is weaker.** Using
  `utils_fpgaIdFromSubcolId` as subcol-from-fpga agrees with the true
  table at **9** `fpga_det` values, {0, 1, 4, 7, 8, 12, 13, 18, 25}. So it
  mis-bins 23 of 32 detectors [C, recomputed].
- `UTILS_SUBCOLID2FPGAID` reads `dete_data[].indexFPGA` (utils.h:116,
  utils.c:74-107), not `utils_fpgaIdFromSubcolId`. The two are equal
  today [C].

Chain (Des §1.4):
```
CSV row (Pixel=pix p, Detector=subcol d, edges e[0..30])
  -> TC(237,7) struct: det_id_1based = d+1, pix = p, B[0..32]
  -> FSW RAM ELUT[d][p][0..32]                       (LUTMgmt.c:1024-1067)
  -> applyELUT: for fpga_det f: d = utils_subcolIdFromFpgaId[f]
       FPGA val[p][f][adc] = ebin(B of row (d, p), adc)   (LUTMgmt.c:835-975)
```

**One copy of the mapping per language.** DP says that in the model only
`stix_det.c` holds index tables. The host tool needs its own Python copy.
E-1 pins it against the FSW source (both tables plus `dete_data`), and
E-4 pins it against `stix_det.c` once DP D-2 adds the tables (see
"Coordination").

**Residual risk (open question for the user).** The gate proves the
chain TC → FSW → FPGA. It does **not** prove that the CSV column
`Detector` means `subcol`. That rests on the GSW writer, stixpy, ICD
Table 32 and BGAccumulator evidence (Des §1.1, §7.2). If the column were
`fpga_det`, every gate would still pass and the binning would be wrong.
See Open question 2.

## Key facts the plan rests on

### The source file
- **File:** `/home/laszlo/dev/STIX-CONF/elut/elut_table_20260529.csv`
  (READ-ONLY). It is current from 2026-06-15 [G/Des §0].
- `elut_index.csv` uses index 17 twice. **Select by date or file name,
  never by index** [V].
- **Format** [V, re-checked]:
  - 387 lines: 3 header lines, CRLF on every line, then 384 data rows ×
    35 columns (offset, gain, Pixel, Detector, 31 edges);
  - row i is (`pix` = i % 12, `subcol` = i // 12);
  - edges are integers 892..2303, strictly increasing per row; e[0] is
    892..968, and edge 30 (150 keV) is 2223..2303;
  - no two rows with the same `pix` are equal.
- **Header guard:** the header row is the first row whose first cell,
  case-folded, starts with "offset". It needs exactly 35 cells:
  - col 2 contains "pixel";
  - col 3 contains "detector";
  - cols 4..34 contain "adc edge".
  Columns are read **by position** [Des §0].

### Boundaries
- **Count:** the FSW holds 33 boundaries B[0..32] per (`subcol`, `pix`),
  12-bit, in raw `adc` units. No scaling is needed [C: LUTMgmt.c:51,
  commonFSW.h:145-146].
- **Mapping:** B[1..31] = CSV edges e[0..30]. **B[0] = 0** [U, 2026-11-11:
  "lowest ELUT boundary is 0, count everything"]. B[32] = 0.
- **The apply loop, exactly** (LUTMgmt.c:878-930) [C]. Per row,
  iBoundary runs 0..33 in order, and a later write wins:
  - 0: `adc` [0, B0) → 32;
  - 1..32: `ebin` c = iBoundary − 1 gets [B[c], B[c+1]), where B[c+1] = 0
    means 4096;
  - 33: [B32, 4096) → 32, nothing when B32 = 0.
  - With B0 = B32 = 0 there is no 32 anywhere. `ebin` 0 covers
    `adc` 0..e[0]−1, and `ebin` 31 covers e[30]..4095.
  - An all-zero row gives all 31: each channel in turn claims [0, 4096).
    This matches DP "The ELUT".
- **Not validated by the FSW:** monotonicity and the 4095 cap. The tool
  validates them [Des §2].

### TC(237,7) and TC(237,8)
- **TC(237,7)** (Des §3.1, TCData.h:190-198, LUTMgmt.c:1024-1067) [C]:
  - APID 0x5AC, header byte 0x19 (both acks), service 237/7;
  - app data `03 | N | N × 52-byte struct`, with N ≤ 4. The tool
    enforces N ≤ 4 (PIX00479). The GS definition ZIX37703 has no cap, and
    the FSW's static length check rejects N = 5 (262 > 236,
    TCVerifStatic.c:136-167);
  - struct = `det_id_1based u8 | pix u8 | B[0..32] packed 12-bit BE
    (pair k at bytes 3k..3k+2), then B32 in the high 12 bits of a u16
    with a spare nibble 0`. ZIX37703 has the same layout;
  - a full unit is 226 B (SpW 4 + CCSDS 222), with length field 0x00D7;
  - 96 TCs cover the 384 rows exactly (ICD:19597).
  - 226 B is the largest TC ever sent through probe and model. The FSW
    RX buffer is 252 B (configFSW.h:169), so it fits [C]. The first live
    run checks that `stixspw_rx_truncated` stays silent [L].
- **Effect of 237,7:** it only updates the RAM table, executed
  synchronously in the TC task (TcService237.c:283-289). The table is
  never cleared between uploads.
  - Bad IDs give TM(1,8) FID 48457; a bad type gives FID 48437
    (LUTMgmt.c:246-285) [C].
  - **A NOMINAL entry before TC(237,8) does not always discard the
    upload** [C]. `load_lut` writes RAM only when a copy is read
    (LUTMgmt.c:1111-1148, fill at :1140). On a miss it logs "could not
    find LUT" and leaves `ELUT[]` untouched, and nothing else clears it
    (LUTMgmt.c:108-138). So:
    - **with no file for the current ID** (a fresh flash, ID 0): the
      NOMINAL-entry reload (OpModeMgmt.c:320) misses, and `applyELUT`
      (:582) writes **the uploaded RAM table** to the FPGA. It goes live
      but does not persist;
    - **with a file for the current ID** (e.g. a re-upload on a seeded
      flash): the reload overwrites the upload, which is lost.
  - Des §3.1 has the old reading ("always discards"); see
    "Coordination".
- **TC(237,8):** app data `03 | lut_id u16`, length field 8 [C:
  TCData.h:225-226, TCData.c:51]. The LUT task (TaskManager.c:146-151)
  then:
  1. runs `applyELUT` (FPGA written at once);
  2. stores 4 file copies (`CONFIG_NUMBER_OF_LUT_COPIES`);
  3. sets `CONFIG_CURRENT_ELUT_ID`;
  4. sends the one TM(1,7).
  Failures are TM(1,8) FID 48438 / 48448 / 48449 [C, Des §3.2].
- **Modes:** both TCs are accepted only in CONFIGURATION or MAINTENANCE
  (TCVerifDynamic.c:81-82) [C].
- **CRC:** CRC-16/CCITT-FALSE over the CCSDS packet. **The probe has no
  CRC code** [C: no crc in tmtc-probe.py]. The existing gates hard-code
  the units with precomputed CRCs (nominal-smoke.sh:146-151:
  0x4AC1, 0xAFBA, 0xBF97, 0x16B8, recomputed). They are E-1's test
  vectors.
- **Acks:** the TM(1,x) data is `1DAC` plus 4 hex digits of
  `0xC000 | seq` (e.g. `1DACC010`), never "C + 3 digits".

### Persistence and the context
- **At boot:** `ContextMgmt_init` runs before `LUTMgmt_init`
  (OpModeMgmt.c:976-982). `LUTMgmt_loadLUTs` reads the ELUT ID from
  `CONFIG_CURRENT_ELUT_ID` (default 0, from the flash context,
  ContextMgmt.c:1591) and fills only the RAM table. **The FPGA ELUT is
  written at the CONF→NOMINAL entry**, not at boot
  (OpModeMgmt.c:317-320, 580-597) [C].
- **A non-zero ID needs the context:** it lives in RAM until a NOMINAL
  entry stores the context (OpModeMgmt.c:317; stored only when its CRC
  changed, ContextMgmt.c:2065-2090). **So the procedure enters NOMINAL
  once after the apply** [C, Des §3.2].
- **Event order at the NOMINAL entry:** `setMode(NOMINAL)` runs the
  whole NOMINAL case, including the ELUT re-apply wait loop, *before*
  `sendSuccessReport` (OpModeMgmt.c:709-725, 805-835) [C]. So TM(5,1)
  `0021 04 05` and the TC's TM(1,7) mean "re-apply finished". The gate
  dumps after them.
- **What proves persistence.** Because a missed load keeps the RAM
  table, **r1-nominal (run 1, after NOMINAL) does not prove the flash
  round trip**: a failed load would still pass it. The proof is run 2's
  conjunction:
  - no TC(237,7) in run 2, so RAM `ELUT[]` (static, zero in a new
    process) can only be filled by `load_lut`;
  - r2-nominal PASS;
  - `could not find LUT (type=3` and `problem reading LUT (type=3`
    absent from the run-2 UART.
- **FSW quirk:** `fill_buffer` and `fill_table` walk 16 896 packed
  entries over a 25 344-B table. They read and write **8 448 B past
  `ELUT[]` into `Tmno`** (sky LUT); in the baseline ELF `Tmno` directly
  follows `ELUT` [C/Des §3.2]. It is harmless on our flashes (no sky LUT
  file, `Tmno` all zero) and flight behaves the same. **Recorded, not
  modelled or fixed.**

### What TM and UART can show
- **0x542C:** its param is one byte (TM_5.c:265-270), and
  `E_LUTMGMT_ELUT` = 3 (LUTMgmt.h:11-15) [C].
  - **ELUT apply error = `0x5A7:5:2:542c03`.** It is near-vacuous:
    `applyELUT` fails only on cancel or the bounds check (:858-930),
    which 12-bit fields cannot hit. It stays as a cheap tripwire.
  - The 0x542C seen today at NOMINAL is p1 = 1 (T1LUT, missing
    temperature LUTs, LUTMgmt.c:466-471) [G: accepted-diffs §23]. It is
    **not** about the ELUT, and loading the ELUT does not remove it.
  - It fires only when temperature correction is enabled (the
    `createNoCorrection` path, LUTMgmt.c:145 vs :168-172), and at most
    once per boot: `LUTMgmt_resetErrorReportSendFlag` has no caller [C].
- **UART:** LUTMgmt's `TRACE` is compiled out (configFSW.h:90,
  LUTMgmt.c:31-34) [C], so "stored/read LUT successfully" never appears.
  Only `TRACE_ERROR` lines do:
  - `could not find LUT (type=3, id=0, ret=0)` at every boot today
    (golden lines 44-47 for types 1..4; LUTMgmt.c:1146) [G];
  - `problem erasing LUT type=3 … expected for the first time`, ×4 at
    the first store (LUTMgmt.c:794) [C, L];
  - `problem writing LUT` on a store failure (LUTMgmt.c:802) [C];
  - `problem reading LUT` for a bad copy that `load_lut` skips
    (LUTMgmt.c:1129) [C];
  - `ELUT update got cancelled` (:865) and `DetectorsApi_setElut(`
    (:926) on an apply failure [C].
- **Fresh flash:** a fresh flash gives TM(5,3) 0x8030 at connect (no
  context). A flash that has seen a NOMINAL entry with a changed
  context must not [G: nominal-smoke.sh connect group; Des §3.3].

### The model side
- The SRAM at 0xE0000000 is a 2 MiB RAM region, `stixctrl.sram`
  (grlib_stixctrl.c:954-973, StixIdpu.h:252-259, leon3.c:466) [C]. It is
  **zeroed at power-on per QEMU process**. Nothing writes the ELUT at
  boot: the only writers are `applyELUT` and `Detectors_clearELUT`,
  which is reached only through a TC EDAC enable (HWConfig.c:95) [C].
- QMP `pmemsave` of 1 572 864 B (12 × 32 × 4096) dumps the FPGA ELUT
  with no model change [Des §3.4]. Filenames are absolute paths.
- **Probe:** `--qmp PATH` / `--qmp-cmd JSON` send groups take any
  `execute` (tmtc-probe.py:216-228). They fail on an error reply or no
  reply within 5 s [C].
  - Sends are at **fixed offsets**: a send cannot wait for a TM.
  - But the probe exits rc 1 at the first expired window (`gate_done`,
    tmtc-probe.py:457-474). So a missed dependency stops every later
    send, **provided each window closes before the dependent send**
    (D-Ee).
  - A forbid arms at its group's send; the data prefix matches from TM
    SP[16] (tmtc-probe.py:96-112, 477-501) [C].
- **Flash writes:** the model `fflush`es every page before the
  completion IRQ (grlib_stixflash.c:384-389), so killing QEMU after a
  TM(1,7) loses nothing [C]. The TMTC listener sets `SO_REUSEADDR`
  (tmtc_io_server.c:350), so run 2 can rebind the port at once [C].
- **Ports, run dirs and lock: GP's slot scheme** (D-G1/D-G2,
  `scripts/stix/lib/slot.sh`, `stix_slot_setup`) [U: coordinator].
  - `STIX_PORT_BASE` unset = legacy slot 0: port 20000+uid, no lock
    taken (the caller holds `/tmp/stix-qtest-21000.lock`), the default
    run dir, and no `-global tmtc-port` on the QEMU line.
  - `auto` or a slot number k ≥ 1: the helper takes the slot lock and
    exports `STIX_SLOT`, `STIX_PORT_BASE` and `TMTC_PORT`. The run dir
    becomes `<default>-s<k>`, and QEMU gets
    `-global grlib-stixspw.tmtc-port=$TMTC_PORT`.
- **Disk:** a run dir's `flash.bin` is a 16.5 GiB **sparse** file
  [G: memory/README]. The real free space is on the Windows host C:
  (`df /mnt/c`: 19 GB free, about 13 GB usable); WSL's `df /` misleads
  [coordinator, GP D-G7]. **A non-sparse copy of one flash would fill the
  disk.** GP's `stix_disk_guard` (`df --output=avail /mnt/c` ≥
  `STIX_DISK_MIN_GB`, default 3) runs before QEMU in every mode.

## Decisions (D-E)

- **D-Ea: delivery by TC through the probe** (Des §4a). Pre-seeding
  flash.bin offline is rejected: it would mean reimplementing the BSW file
  system, BCH ECC and the context files (Des §4b).
- **D-Eb: B0 = 0, B32 = 0, fixed** [U]. There is no `--b0` option, and the
  run log records "B0=0 B32=0 (user decision 2026-11-11)". If ops ever
  confirm another E0-low, that is a one-line change plus an accepted-diffs
  note.
- **D-Ec: LUT ID default 1** (`--lut-id`, 0..65535). A non-zero ID
  exercises the context path, which is the realistic case. ID 0 stays
  possible, but the gate uses 1.
- **D-Ed: the CSV is referenced by path only.** It comes from `--csv` or
  `STIX_ELUT_CSV`. It is never copied into the repo or the run dir, and
  no test needs it. The run log records the path, sha256, row count and
  value ranges, not the rows.
- **D-Ee: pacing and windows.** One TC(237,7) every 0.75 s. **Each one
  must get TM(1,1) and TM(1,7)**, and TM(1,8) is forbidden for the whole
  run.
  - The probe cannot gate a send on an ack. So the rule is: **every
    expectation window that guards a later step ends before that step's
    send.** The gate sets `--window 10` and an explicit `@W` on every
    guarding expectation (the E-2 tables list them):
    - CONF at 35 with `@12` (closes 47) and S20=0 at 40 with `@8`
      (closes 48), before the first dependent send at 50;
    - each TC(237,7) TM(1,7) `@5`. The last one is sent at 121.25 and
      closes at 126.25, before TC(237,8) at 127;
    - the TC(237,8) TM(1,7) `@38` closes at 165, 10 s before the NOMINAL
      send at 175 (the r1-apply dump at 170 sits in between).
  - If the apply is slower, the gate fails on that expectation instead
    of racing the NOMINAL reload. Then widen the window and move the
    later rows; never shorten a gap.
  - Belt and braces: 237,7 is executed synchronously in the TC task, so a
    later TC cannot overtake it anyway.
  - **Apply time evidence:** nominal-smoke already gets its NOMINAL
    TM(1,7) within `--window 20` with an all-zero-table apply, which
    writes about 33× more entries (each channel claims [0, 4096)). So
    `@38` is generous [G/I]. Record the measured time.
- **D-Ef: the checker models the FSW loop, not a formula.** For each
  (`pix`, `fpga_det`) it takes `subcol = SUBCOL_FROM_FPGA_DET[fpga_det]`.
  It replays LUTMgmt.c:878-930 literally, last write wins, and compares
  all 1 572 864 bytes. A mismatch is reported as
  `pix fpga_det subcol adc want_ebin got_ebin`, with the first 20 shown
  and a count per (`pix`, `fpga_det`).
  - **Plus an independent oracle, on every dump check**, taken directly
    from the CSV edges (no B[], no loop replay). Without it, a shared
    boundary-builder bug (e.g. B[c] = e[c] with no B0 shift) would make
    encoder, FSW and checker agree. For every (`pix` p, `fpga_det` f)
    with e = CSV row (`subcol` = SUBCOL_FROM_FPGA_DET[f], p):
    - `val[p][f][0] == 0`;
    - `val[p][f][e[k]−1] == k` and `val[p][f][e[k]] == k+1` for
      k = 0..30;
    - `val[p][f][4095] == 31`.
- **D-Eg: the checker proves its own sensitivity** on every real check:
  - it computes the table under the **identity** mapping and under the
    **wrong-direction** mapping (`utils_fpgaIdFromSubcolId` used as
    subcol-from-fpga);
  - for each it requires **exactly the predicted number of differing
    rows**, `12 × #{f : wrong[f] ≠ true[f]}` (identity 348, wrong
    direction 276), with every predicted row differing. Otherwise it
    exits 2 ("checker cannot detect a mapping bug on this CSV") [V:
    348 / 276 recomputed on the real CSV].
- **D-Eh: negative controls in the gate.**
  - A dump taken in CONF before any apply in that QEMU process must
    **fail** the checker and be **constant 0** (power-on zero RAM).
    All-31 would mean an unexpected apply before CONF.
  - Run 1 takes one before the upload, and run 2 one before the NOMINAL
    entry.
  - What they prove: no FPGA content carries over and nothing applies at
    boot. They do **not** by themselves prove the flash load. That is
    the run-2 conjunction under "What proves persistence".
- **D-Ei: the gate is optional.** Without `STIX_ELUT_CSV` (or with an
  unreadable file), or without the ASW ELF, it prints `SKIP: …` and
  exits **77** [U: the optional-gate convention, as DP D-7]. In
  `test-elut-upload.sh`, the `STIX_FSW_SRC` cross-check is a sub-check,
  not a gate skip. It prints `SKIP (fsw-src): …` and the script's rc
  comes from the other checks, so a missing source tree never hides the
  host tests.
- **D-Ej: ports, run dir and lock from GP's `lib/slot.sh`** (Key facts,
  "The model side") [U: coordinator]:
  - `source scripts/stix/lib/slot.sh` and `stix_slot_setup`: GP's
    two-line pattern from §41. `STIX_ELUT_RUN_DIR` defaults to
    `/tmp/stix-elut-run`, and the helper makes it `-s<k>` in slot mode;
  - the nominal-smoke guard (canonicalise; refuse `/`, the shared
    uprev/baseline run dirs, their parents and children);
  - `TMTC_PORT` goes to the probe as `--port`, and in slot mode to QEMU
    as `-global grlib-stixspw.tmtc-port=`; the `ss` busy check runs on
    that port;
  - QMP at `<run dir>/qmp.sock` (< 108 bytes);
  - `stix_disk_guard` before each QEMU start and before
    `--save-template`.
- **D-Ek: disk hygiene** [coordinator constraint, GP D-G7]:
  - SRAM dumps (up to 6 × 1.5 MiB) go to the run dir. **They are
    deleted after a passing gate and kept after a failure**, for
    diagnosis.
  - The gate prints flash.bin's apparent and allocated size at the end.
  - A template copy is made only by an explicit `--save-template PATH`,
    and **it runs before the PASS cleanup**. In slot mode GP's PASS
    cleanup deletes the slot dir's `flash.bin`, so the seeded flash
    survives only as the template. In legacy mode it also stays in the
    run dir until the next elut-smoke run.
- **D-El: the template copy, pre-flighted and checked.**
  - **Before the copy:**
    - refuse a target under `/mnt/`, and require `stat -f -c %T` of the
      target dir to be ext2/ext3 (ext4), xfs, btrfs or tmpfs: a
      filesystem without holes would write all 16.5 GiB before any check;
    - refuse an existing target, the guarded shared dirs, and a target
      whose path is the source;
    - `stix_disk_guard`.

### E-1: `scripts/stix/elut-upload.py` (stdlib CSV → TC encoder, dump checker)

Test first: write `scripts/stix/tests/test-elut-upload.sh` and the
`self-test` cases, see them fail, then implement.

- **Subcommands:**
  - `encode --csv PATH --lut-id N --first-seq S --t0 SECONDS --pace 0.75
    --emit probe-args|hex`;
  - `check-dump --csv PATH --dump FILE [--expect-constant V]`;
  - `self-test`.
  - `--csv` defaults to `STIX_ELUT_CSV`.
  - Exit codes of `check-dump`: 0 pass, 1 mismatch, 2 environment or
    sensitivity failure. `--expect-constant V` turns "constant V" into
    exit 0 and anything else into 1.
- **`encode --emit probe-args` prints one probe argument per line**, read
  by `mapfile -t`:
  - per TC k, `--send-at t0+0.75k --send-hex UNIT --expect
    0x5A1:1:1:1DACxxxx@5 --expect 0x5A1:1:7:1DACxxxx@5`, where xxxx =
    4 hex digits of `0xC000 | seq`;
  - then TC(237,8) at t0 + 0.75·96 + 5 (= 127 for t0 = 50) with TM(1,1)
    and `TM(1,7)@W_APPLY` (38).
  - `hex` prints one unit per line.
  - stderr gets the record line (path, sha256, rows, edge range, LUT ID,
    "B0=0 B32=0").
- **Names in the code:** `rows[(subcol, pix)]`, `det_id_1based`,
  `SUBCOL_FROM_FPGA_DET` / `FPGA_DET_FROM_SUBCOL` (each with its
  utils.c:113-119 / :121-127 comment), and `val[pix][fpga_det][adc]`.
- **Parser** (D-Ed, Key facts):
  - `csv` with `newline=''`; the header guard;
  - position columns; exactly 384 rows; each (`subcol`, `pix`) once;
  - integer edges strictly increasing in 1..4095;
  - an error names the CSV line and the index space ("row 17: subcol 1
    pix 5: edge 12 not > edge 11").
- **`check-dump`** runs D-Ef (loop replay plus the independent oracle)
  and D-Eg (exact sensitivity counts) on every call.
- **`self-test`** (no file needed; it builds a synthetic CSV in memory
  with edges `100 + 60k + (12·subcol + pix)`, so every row is unique:
  the term is 0..383, the max edge is 2283, and rows stay strictly
  increasing):
  1. **CRC:** the four nominal-smoke units rebuild byte for byte.
  2. **Round trip:** every encoded unit decodes, through a Python copy of
     processELUT (LUTMgmt.c:1024-1067), to
     `subcol = det_id_1based − 1`, the same `pix` and 33 boundaries.
     Length field 0x00D7, spare nibble 0, N ≤ 4, 96 units.
  3. **Off-by-one trap:** a unit built with `det_id_1based = subcol`
     must decode to the wrong row. `subcol` 0 must hit the FID 48457 range
     check (uint32 wrap).
  4. **Identity trap:** a dump built with `fpga_det = subcol` must FAIL
     `check-dump`, with exactly 29 × 12 bad rows. The correct dump passes.
  5. **Wrong-direction trap:** a dump built with `FPGA_DET_FROM_SUBCOL`
     in place of `SUBCOL_FROM_FPGA_DET` must FAIL, with exactly 23 × 12
     bad rows.
  6. **Axis trap:** a dump laid out `[fpga_det][pix][adc]` must FAIL.
  7. **Shared-builder trap:** a dump built from a shifted B[] (B[c] =
     e[c], B31 = B32 = 0) must FAIL the independent oracle even though
     the loop replay of the same shifted B[] agrees.
  8. **Constant dumps:** all-0 and all-31 FAIL and are reported as
     constant with their value; `--expect-constant 0` / `31` turns that
     into exit 0, and the other value into exit 1.
  9. **Tables:** both are permutations, inverse to each other, with fixed
     points exactly {0, 1, 4}, and agreeing exactly at {0, 1, 4, 7, 8,
     12, 13, 18, 25}.
  10. **Apply loop, from e[] (not from B[]):** an all-zero boundary row
      gives all 31 (DP "The ELUT"). For a CSV row, `ebin` 0 at
      `adc` e[0]−1 and 1 at e[0], 31 at e[30] and at 4095, and no 32.
- **`tests/test-elut-upload.sh`** (plain bash, temp dir, like
  test-soak.sh):
  - runs `self-test`;
  - writes synthetic CSVs in a temp dir: LF, CRLF, a leading-space
    header line, wrong header name, 34 columns, 383 rows, a duplicate
    pair, a non-monotone row, an edge 0 and 4096;
  - asserts pass/fail and the error text for each;
  - golden-checks the first unit's hex for the synthetic CSV;
  - **when `STIX_FSW_SRC` is set**, parses both tables and the
    `dete_data[].indexFPGA` column from `utils.c` and compares them with
    the Python copy (read-only). Otherwise it prints
    `SKIP (fsw-src): …` (D-Ei).
- **Gate:** the test script, `self-test`, the probe self-test (unchanged),
  `python3 -m py_compile`. No QEMU.

  sha256 and ranges in the commit message (no data).

## DSS replay caveat

- The `.dssevs` events sit on a baseline of about 2000 with lines at
  2182-3820. The flight ELUT has 0 keV at about 855-931 and 150 keV at
  2223-2303 [V].
- With B0 = B32 = 0, `adc` 2000 → `ebin` 29/30, 2100-2182 → 30, and
  ≥ 2300 → 31 (Des §5) [V]. **On an ELUT-loaded flash the replay lands
  almost entirely in `ebin` 30/31**, outside the LC bands (1-27) and
  outside D-7's checks (`ebin` 2-28).
- Not a bug: the DSS bench ADC scale is not the flight calibration [I].
- **Effect on D-7: none through the gates.** detector-smoke deletes its
  own flash at every start (DP D-3, "a fresh flash"), and its connect
  group expects 0x8030. A seeded flash cannot reach the D-7 gate.
  - The real exposure is the GS/template path: a replay started by hand
    on a template or on a GS run dir holding one.
  - Pointing `STIX_DETECTOR_RUN_DIR` at the ELUT run dir would only
    delete the seeded flash.
- Stated in the elut-smoke header, ground-station.md and §40. A
  "replay on flight ELUT" ADC remap is out of scope.

## Risks and checks

- **Mapping mistakes** are the main risk. They are covered by D-Ef (with
  its independent oracle) and D-Eg (exact counts), by the self-test traps
  (identity, wrong direction, axis swap, off-by-one, shared builder), by
  the negative controls (D-Eh, `--negative`) and by the FSW-source
  cross-check. The live gate is self-validating against the real FSW:
  any error in the Python table makes it fail.
- **CSV semantics** (`Detector` = `subcol`) cannot be checked by any
  gate. Open question 2.
- **The gate ELF vs the FSW source:** every [L] is confirmed live before
  it becomes an expectation. These are the 0x542C encoding, the 4
  erasing lines, run 2's 0x142E, the dump constants, the apply time and
  the RX truncation trace.
- **The apply time in QEMU** is unmeasured but bounded (D-Ee). If
  TC(237,8)'s TM(1,7) misses @38, widen the window and move the later
  rows. Never shorten a gap.
- **TC burst tolerance:** the FSW TC buffer holds 64 packets
  (configFSW.h:172), far above 0.75 s pacing. Each TC must get its
  TM(1,7). If TM(1,2)/TM(1,8) shows up, go to 1.0 s (+24 s).
- **The context write and the QEMU kill:** the context and LUT files are
  written before the NOMINAL TM(1,7), and the model flushes every page
  (grlib_stixflash.c:384-389). The run ends ≥ 50 s later. Run 2 is the
  proof.
- **The run dir becomes a seeded flash.** The header, the docs and the
  0x8030 connect expectation of the other gates protect them.
  elut-smoke wipes its own flash at every start.
- **Disk:** only sparse copies, pre-flighted and verified (D-El). No dump
  survives a pass. `stix_disk_guard` before each QEMU start.
- **Ports and lock:** GP's scheme (D-Ej).
